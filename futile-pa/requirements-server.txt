# Complete pinned dependency manifest for the personal-context-mcp server,
# covering both the MCP SDK stack and futile-pa.
#
# WHY THIS FILE EXISTS
#
# The project had no manifest at all — dependencies lived only in a virtualenv,
# and had to be reconstructed from imports and site-packages when that venv broke.
# That alone is worth fixing. But the sharper reason is what happened on
# 2026-09-16: `pip install mcp`, unpinned, resolved to mcp 2.2.0. The 2.x
# low-level Server class dropped the .list_tools() / .call_tool() decorators that
# server.py is built on, so a restart would have taken down all 29 tools at once,
# with a traceback pointing at a file nobody had edited. It was caught only
# because a pre-restart smoke check failed loudly.
#
# An unpinned dependency on a library that makes breaking major releases is a
# scheduled outage with no date on it. Hence hard pins.
#
# INSTALL
#     cd /home/dremon/tools/personal-context-mcp
#     ./.venv-new/bin/pip install -r /home/dremon/futile-pa/requirements-server.txt
#
# UPGRADING
#     Bump one line at a time. After any change to mcp, starlette or uvicorn,
#     verify the decorator API still exists before restarting the live server:
#         ./.venv-new/bin/python -c "from mcp.server import Server; \
#             s=Server('t'); assert hasattr(s,'list_tools') and hasattr(s,'call_tool'); print('ok')"
#     After any change to psycopg or python-dateutil, run the 63-check suite
#     against a scratch database:
#         createdb pa_scratch
#         PA_DATABASE_URL='postgresql://localhost/pa_scratch' python tests/test_smoke.py
#         dropdb pa_scratch
#
# Versions below are the set verified running together on 2026-09-16:
# Python 3.13.5, PostgreSQL 18.6, Debian.
